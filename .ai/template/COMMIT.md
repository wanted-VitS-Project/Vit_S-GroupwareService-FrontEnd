# 📝 커밋 메시지 양식

> 🚫 **커밋은 사용자가 직접 한다.** AI 는 `git commit` / `git add` / `git push` 를 실행하지 않는다.
> 아래 양식대로 **메시지 텍스트만 제공**하면 사용자가 복사해서 직접 커밋한다.

---

## 양식

```
[TYPE] 한 줄 요약 (#이슈번호)

- 변경 사항 1
- 변경 사항 2
- 변경 사항 3
```

## 타입 (대괄호 + 대문자)

| 타입          | 사용 시점            |
| ------------- | -------------------- |
| `[FEAT]`      | 신규 기능 추가       |
| `[FIX]`       | 버그·오류 수정       |
| `[REF]`       | 리팩토링 (동작 동일) |
| `[STYLE]`     | UI·CSS 수정          |
| `[DOCS]`      | 문서 작성·수정       |
| `[TEST]`      | 테스트 추가·수정     |
| `[CHORE]`     | 빌드·설정·의존성     |

## 작성 규칙

- 요약은 **명령형 현재시제**, 마침표 없이. (`추가함` ❌ → `추가` ✅)
- 요약 줄은 50자 이내 권장.
- 본문 bullet 은 **2~4개**. 실제 변경 파일 기준.
- 이슈 번호가 없으면 `(#이슈번호)` 를 생략한다.
- 하나의 커밋에 서로 다른 성격의 변경을 섞지 않는다.

## 예시

```
[FEAT] 로그인 페이지 폼 구현 (#12)

- LoginForm 컴포넌트 추가 (이메일/비밀번호 입력)
- useLogin 훅으로 API 연동
- 유효성 에러 메시지 표시
```

```
[CHORE] ESLint · Tailwind 설정 정리 (#3)

- eslint-config-next 규칙 적용
- globals.css Tailwind 지시자 정리
```
