# 🔀 PR 작성 양식

> 🚫 **PR 생성은 사용자가 직접 한다.** AI 는 `gh pr create` 등을 실행하지 않는다.
> 아래 양식대로 **제목 + 본문 텍스트만 제공**하면 사용자가 복사해서 직접 올린다.

---

## 제목

`[TYPE] 작업 내용` 형식 (대괄호 + 대문자).

| 타입          | 사용 시점            |
| ------------- | -------------------- |
| `[FEAT]`      | 새로운 기능 추가     |
| `[FIX]`       | 오류·버그 수정       |
| `[REF]`       | 리팩토링·구조 개선   |
| `[STYLE]`     | UI·CSS 수정          |
| `[DOCS]`      | 문서 수정            |
| `[TEST]`      | 테스트 추가·수정     |
| `[CHORE]`     | 빌드·설정·의존성     |

예: `[FEAT] 로그인 페이지 구현`

> 릴리즈 PR(`develop → main`)만 예외로 `[Release] vX.Y.Z` 형식. ([PIPELINE.md](../PIPELINE.md))

---

## 본문 (일반 PR)

`.github/PULL_REQUEST_TEMPLATE/PULL_REQUEST_TEMPLATE.md` 를 따른다.

````markdown
## 📌 관련 이슈
- close #

## 📁 작업 유형
- [ ] 새로운 기능 추가 [FEAT]
- [ ] 버그 수정 [FIX]
- [ ] 코드 리팩토링 [REF]
- [ ] UI 및 CSS 수정 [STYLE]
- [ ] 문서 수정 [DOCS]
- [ ] 테스트 추가 및 수정 [TEST]
- [ ] 빌드/설정 등 기타 [CHORE]

## ✨ 작업 내용
-

## 🧩 변경 이유
-

## 🔍 기타
-

## 📸 스크린샷
> UI 변경이 있다면 첨부해주세요.
````

---

## 작성 규칙

- 작업 유형 체크는 제목의 타입과 **동일하게 1개만**.
- 이슈 번호는 `close #N`. 다중 이슈는 `close #N + close #M`.
- 작업 내용은 실제 변경 코드 기준 **2~4개 bullet**.
- 모듈 경로는 `src/...` 형식으로, 실제 변경 파일을 보고 판단.
- 확인 불가한 항목은 **"확인 필요"** 라고 적는다. 지어내지 않는다.
- 프론트 번들에 노출되는 값(`NEXT_PUBLIC_*`)에 비밀키가 없는지 확인.
