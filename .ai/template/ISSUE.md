# 🎫 Issue 작성 양식

> 🚫 **이슈 생성은 사용자가 직접 한다.** AI 는 `gh issue create` 등을 실행하지 않는다.
> 아래 양식대로 **제목 + 본문 텍스트만 제공**하면 사용자가 복사해서 직접 올린다.
> GitHub 이슈 템플릿(`.github/ISSUE_TEMPLATE/`)을 쓰면 본문 골격과 라벨이 자동 적용된다.

---

## 템플릿 선택

| 템플릿      | 파일            | 용도                          | 제목             | 라벨(자동)   |
| ----------- | --------------- | ----------------------------- | ---------------- | ------------ |
| ✨ Feature  | `new-issue.yml` | 새로운 기능 추가 요청         | 기능명 간결하게  | `feature`    |
| 📒 Task     | `task.yml`      | 문서·설계·조사 등 일반 업무   | `[TASK] 작업명`  | `Type: Task` |

---

## Feature 본문

````markdown
## 📄 설명
[무엇을 구현할지 간단히]

## ✅ 작업할 내용
- [ ] 최대한 세분화해서 적기
- [ ]

## 🙋🏻 기타
[링크·문서·이미지 등 — 없으면 "없음"]
````

---

## Task 본문

````markdown
## 👤 담당자
- [ ] 서민지
- [ ] 손윤서

## 📝 개요 (Context)
[이 작업이 왜 필요한지, 어떤 배경에서 시작되었는지]

## 🎯 댓글 양식
[완료 시 댓글로 남길 결과물 — 예: 컴포넌트 명세 노션 링크]

## ✅ 액션 아이템
1. [작업 1]
2. [작업 2]

## 📅 기한
2026.00.00 (요일) 00:00

## 🔗 참고 자료 및 의존성
[선행 이슈 #N, 노션 링크 등]
````

---

## 작성 규칙

- 작업 성격을 보고 템플릿을 고른다. (기능=Feature, 그 외=Task)
- 작업 내용은 체크박스로 세분화한다.
- 확인 불가한 항목은 **"확인 필요"** 라고 적는다. 지어내지 않는다.
- 담당자·라벨·마일스톤은 GitHub 우측 필드/본문 체크박스로 지정한다.
